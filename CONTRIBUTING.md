# Contributing

Contribute a focused fix or a useful maintained integration. Include a reproducible
synthetic example, the exact native dependency version, input/error boundaries and
regression tests. Keep optional framework dependencies optional. Do not add raw
resolver outputs to agent state, traces or model-facing responses.

Run the Node suite, Python tests and relevant distribution checks. Shared and
packaged vault-core copies must remain identical. Preserve licence notices and
record changes that affect vault migration or compatibility. Source changes must
not silently replace a user's data or rewrite a previously published version.

AI-assisted contributions are welcome when their author verifies the code,
licensing, test results and technical claims. No claim of upstream adoption or
independent audit should be made without evidence. Read SECURITY.md before
reporting a sensitive issue. Use synthetic data and never commit credentials.

For visibility, prefer a working adapter, documented example and requested technical
contribution. Read the target project's contribution policy and check existing
threads before contacting maintainers. Do not mass-post, solicit fake engagement,
bump declined proposals or publish private contact/no-contact records.
