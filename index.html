A narrower, testable execution boundary

Agent: operation name ? Authenticated local broker ? Fixed destination + credential ? HTTP status only

Authenticated storage

Argon2id and AES-256-GCM cover the complete vault entry set, including names and domain bindings. Migration is explicit and preserves the original source/data versions.

Deliberate execution

Approved GET/HEAD operations use validated destinations. Redirects are refused. Upstream bodies and headers are discarded; the caller receives status, not the returned payload.

Inspectable delivery

Executable regression tests, native-framework runs, clean package installs and a built-source container accompany versioned artifacts and checksums.

Explicit limits, not absolute security slogans

Raw resolution is disabled by default and cannot share a transport with broker mode. A compromised operating system or broker process is outside this boundary. Hostile code-executing agents require a separate OS/container security boundary.

The historical browser/PWA, GUI, IDE and mobile wrappers have separate validation status. They are not interchangeable with the new Node vault format, and their presence in the repository does not mean a new store release exists.
